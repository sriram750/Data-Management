# DataMatrix - Role-Based Access Control (RBAC) Guide

DataMatrix implements a multi-tier authorization and security model spanning application permissions, table permissions, column-level protection, and record-level filtering rules.

---

## 1. Role Hierarchy

Upon initial setup, DataMatrix automatically provisions 6 system roles:

| System Role | Code | Description | Default Capabilities |
|---|---|---|---|
| **Super Admin** | `SUPER_ADMIN` | Unrestricted root administrator. | Full access to all tables, columns, settings, user management, and encryption keys. |
| **Application Admin** | `APPLICATION_ADMIN` | System administrator without raw secret reveal. | Manage users, configure roles, build tables, view audit logs. |
| **Manager** | `MANAGER` | Department or team supervisor. | Manage tables, create/edit/delete records, export data, manage columns. |
| **Data Entry** | `DATA_ENTRY` | Operational data contributor. | Add and edit records in permitted tables. Cannot delete records or change schema. |
| **Viewer** | `VIEWER` | Read-only auditor/viewer. | View records in permitted tables and permitted columns. Cannot edit or delete. |
| **Auditor** | `AUDITOR` | Compliance officer. | Read-only access to Audit Logs, Sensitive Access Logs, and Table Revisions. |

---

## 2. Granular System Permissions (22 Capabilities)

Permissions are organized into 5 functional categories:

### Table Management
- `tables:view`: View list of tables.
- `tables:create`: Build and provision new dynamic tables.
- `tables:edit`: Edit table metadata, display name, and description.
- `tables:delete`: Permanently delete a dynamic table and its records.
- `tables:manage_columns`: Add, modify, reorder, or delete columns.
- `tables:manage_permissions`: Grant role permissions on tables and columns.

### Record Management
- `records:view`: View data records in permitted tables.
- `records:create`: Insert new records into permitted tables.
- `records:edit`: Modify existing records in permitted tables.
- `records:delete`: Delete individual or bulk records.
- `records:restore`: Roll back records to earlier revision versions.

### Import / Export
- `import:execute`: Import spreadsheet files (.xlsx) into new or existing tables.
- `import:view_history`: View historical import jobs and validation logs.
- `export:execute`: Export permitted table records to XLSX or CSV format.
- `export:view_history`: View historical data export logs.

### Security & User Administration
- `users:manage`: Create, edit, disable, or delete user accounts.
- `roles:manage`: Create, edit, and assign custom roles and capability matrices.
- `sessions:manage`: Monitor and revoke active authenticated user sessions.
- `secrets:reveal`: Explicitly reveal AES-256 decrypted passwords (generates `PASSWORD_VIEWED` audit entry).

### Audit & Governance
- `audit:view`: Query and inspect system audit trails.
- `audit:view_sensitive`: Query dedicated logs for password views and sensitive exports.
- `settings:manage`: Modify global security thresholds, lockout duration, and LDAP directory connections.

---

## 3. Column-Level Permission Protection

DataMatrix allows setting explicit access levels for individual columns on a per-role basis:

1. **`VIEW_EDIT` (Full Access)**: Role can view and modify cell values for this column.
2. **`VIEW` (Read-Only)**: Role can view the column in the grid and exports, but cannot edit.
3. **`DENIED` (Hidden & Redacted)**:
   - The column is completely stripped from API response payloads.
   - The column header does not appear in the frontend grid.
   - The column is omitted from Excel and CSV exports generated by this role.

---

## 4. Sensitive Field Security (AES-256-GCM)

Columns marked with `is_sensitive=True` or `data_type='PASSWORD'` are stored as authenticated AES-256-GCM ciphertexts.
- By default, the API returns masked values (`••••••••`).
- To reveal the plaintext value, an authorized user must click **Show**, triggering a call to `/api/v1/tables/:id/records/:recId/columns/:colId/reveal-secret`.
- This operation is strictly audited with a `PASSWORD_VIEWED` log event recording the user ID, timestamp, table, column, record, and client IP address. Plaintext secrets are NEVER written to logs.
